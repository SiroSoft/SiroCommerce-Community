# API-1 Handoff Harness

## Commands

Run from `backend/`:

```text
composer handoff:matrix
composer check:api-contract
composer check:api-handoff
composer test:unit
composer test:integration
composer test:api
composer test:workflow
composer check
```

`handoff:matrix` parses executable route declarations and writes
`docs/api-handoff/coverage-matrix.json`. The matrix has one record per exact
`METHOD path`, with independent Unit, Integration, API/Component, Contract and
Workflow evidence. It does not count route-name references. `PASS` requires a
semantic evidence path; `BLOCKED` and `SKIP` require a reason, owner and issue.

The checked-in override registry is generated by `composer merge:api-evidence`
from independently reviewed domain evidence fragments. Run that command after
adding routes or evidence, then run the handoff gate. Route references alone
never qualify as semantic evidence.

## Artifacts

- `coverage-matrix.json`: complete machine-readable route/layer matrix.
- `latest-result.json`: latest structural/parity counts and readiness.
- `../../public/openapi.json`: public OpenAPI copy.
- `../../generated/sirocommerce.ts`: generated TypeScript SDK.
- `../../tests/Support/ApiFixtures.php`: deterministic fixture factory.
- `../../tests/Support/ApiAssertions.php`: success/error envelope assertions.

OpenAPI and SDK are generated from the route source. The handoff gate checks
route-to-OpenAPI parity, source/public OpenAPI synchronization, and exact SDK
operation parity. It also checks that every non-PASS claim is actionable.
