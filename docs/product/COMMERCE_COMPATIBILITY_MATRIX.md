# Commerce Compatibility Matrix

This matrix is reviewed after every backend round. It is a capability and
behavior comparison, not a claim that all products share the same architecture
or license model.

## Round Gate

No round is complete until:

1. Local PHPUnit runs on MySQL with 0 failures.
2. PHPStan max, security, mapping, i18n, audit, and boundary gates pass.
3. The changed capability is compared against WooCommerce, Bagisto, and
   Magento/Adobe Commerce.
4. Missing capabilities are implemented, explicitly out of scope, or entered
   as a time-bound exception with owner and evidence.
5. The matrix, evidence register, and change record are updated in the same
   commit/release record.

## Comparison Rules

- Compare behavior and operational guarantees, not marketing checklists.
- A third-party extension feature counts only if SiroCommerce has an approved
  adapter/contract and idempotency/failure tests.
- A feature marked `DONE` must have a local test and evidence reference.
- A feature marked `PARTIAL` cannot be advertised as production-ready.
- If a product has a feature outside SiroCommerce's V2 scope, record
  `OUT_OF_SCOPE` instead of inventing an incomplete implementation.
- SiroCommerce may intentionally differ where it provides stronger invariants:
  integer money, immutable snapshots, idempotency, inventory ledger, typed
  hooks, Flight Recorder, Doctor, and verified Recovery.
