## 1. Principles

1. **Platform before volume.** No “one dev, one random plugin” before package,
   license, slots and CI contracts are stable.
2. **Free before Pro.** Free themes/plugins prove the platform; Pro starts only
   when entitlement and scope enforcement exist.
3. **One owner per package.** Platform owners review; plugin owners do not edit
   core.
4. **QIT gate is mandatory.** A package is not “done” until `extension:qit`
   passes and install → enable → disable → uninstall is smoke-tested.
5. **Store/channel scope is not optional** for every `ext_*` table.
6. **No binary compatibility** with Bagisto/Woo; port only when the owner asks.

## 3. Target repo layout

```text
backend/app/Extensions/<Vendor>/<Name>/     # first-party packages
  manifest.json
  Extension.php
  migrations/
  routes.php
  src/
  tests/                                     # package tests in main suite
  README.md
  dist/                                      # local build output (gitignored)
examples/themes/<key>/                       # theme source + assets
  theme.json
  assets/
apps/admin/src/modules/<domain>/             # plugin admin UI modules
docs/contracts/                              # package/theme contracts
docs/engineering/                            # build guides, QIT, operations
```

Rules:
- Packages never edit `backend/app/Modules/*` or `vendor/*`.
- Admin UI for a plugin lives in its module folder and uses shared primitives.
- Theme assets are referenced as `assets/...` inside zip packages; exposed URLs
  are generated by the media/storage layer.
- A theme package must never contain PHP/JS/HTML/SVG.

## 7. Definition of Done (per package)

- [ ] Package id/version/semver; `manifest.json` v2.
- [ ] Provider under `App\Extensions\...`; no core edits.
- [ ] Migrations `ext_*` + `store_id`/`channel_id` (or reviewed global).
- [ ] Routes under `/api/ext/<id>`; auth/cap on mutations; idempotency.
- [ ] Admin UI (if any) uses shared primitives; no arbitrary JS.
- [ ] Storefront slot (if any) named + documented.
- [ ] Unit/integration tests; QIT passes; PHPStan/lint clean.
- [ ] Install → enable → smoke → disable → uninstall tested.
- [ ] README: config, data retention, upgrade, license SKU.
- [ ] Screenshots/preview for themes; real assets, no placeholder brand.
- [ ] Runbook entry if provider/queue/external service involved.

## 10. Cadence and metrics

- Daily 15-minute stand-up; blocker = dependency on D2/D4.
- Weekly demo Friday; package must be installable from a zip.
- Sprint review: show install → use → uninstall, not slides.
- Metrics:
  - QIT pass rate on `main` (target 100%).
  - Packages installable from zip (target 100%).
  - Median time from scaffold to QIT pass.
  - E2E coverage of plugin/theme critical paths.
  - Post-install core health and no residue after uninstall.

## 11. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| License/scope/slots late | Pro plugins blocked | D2/D4 first; D3 works on free plugin independently |
| Marketplace too early | Empty catalog, billing complexity | Ship 3 themes + 2 plugins before marketplace beta |
| Plugin edits core | Upgrade breakage | PR gate + QIT + code owners |
| Unsigned/unsafe packages | Supply-chain risk | Signature required for paid; QIT secret/lint; no SVG/JS |
| Multi-store leakage | Data exposure | Scope check in QIT + review; Affiliate migration first |
| Devs blocked on each other | Low throughput | Freeze contracts week 1; interface owner per area |
