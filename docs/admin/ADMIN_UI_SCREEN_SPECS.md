# Enterprise Admin UI Screen Specifications

Status: documentation-only parallel delivery map

## Source And Counting

The current contract (2026-11-27) contains **469 route declarations / 469 OpenAPI operation IDs** across **406 paths** (OpenAPI `info.version` 0.3.4). The regenerated contract reports **376 bearer-authenticated**, **410 FE-guarded**, and **63 `x-scope`** operations; rerun the handoff before quoting those derived counts. The domain counts below are FE screen ownership counts, not unique API counts: an operation can be reused by more than one screen. Provider/server-to-server operations remain mapped for safe UI states but are excluded from browser certification. The screen map below is a design baseline; it may not list every current operation.

Shared route ownership rules:

- URL paths below are FE route ownership only. API calls must use the listed generated `operationId`.
- Roles are route-middleware navigation defaults. Capabilities are additive and backend authorization remains authoritative.
- `CommerceScope` is `{store_id, channel_id, locale, currency}`. Do not render scoped data until all four values are valid. Cache keys include the complete scope and request parameters.
- Every screen owns loading, empty, success, `401`, `403`, `409`, `422`, `429`, `500`, and unknown-state variants where the operation can produce them. Mutation screens additionally own `unknown_outcome -> reconcile`.
- WCAG 2.2 AA is required: logical keyboard order/no traps, visible focus, labeled controls/errors, focus return from dialogs, 320 CSS px and 400% reflow, reduced motion, 4.5:1 normal-text contrast, and no color-only status.

## Per-Screen Error And Accessibility Acceptance

1. `401` performs one coordinated session recovery, then renders signed-out state; `403` renders a deliberate forbidden state without resource probing.
2. `409` preserves the draft and refetches; `422` maps `meta.errors`; `429` honors `Retry-After`; `500` shows only generic recovery plus correlation ID; unknown state/outcome is explicit and non-destructive.
3. Every mutation has a visible pending state, idempotency behavior matching OpenAPI, and a documented authoritative read before retry after response loss.
4. Every table has a mobile/reflow representation, every dialog traps and restores focus, every status is available to assistive technology, and every destructive action has a named confirmation.
5. Automated axe has zero critical/serious findings on each route. Evidence records route, operationId, browser, viewport, zoom, assistive technology, and test ID without raw PII.
